# Metadata

## Routing Metadata

- The Metadata API in Next.js is a powerful feature that lets us define metadata for each page.
- Metadata ensures our content looks great when it's shared or indexed by search engines.

### Two ways to handle metadata in `layout.tsx` or `page.tsx`

1. Export a static `metadata` object.
2. Export a dynamic `generateMetadata` function.

### Static Metadata Example

```tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "Home Page",
  description: "Welcome to my website",
};

export default function Home() {
  return <h1>Home Page</h1>;
}
```

### Dynamic Metadata Example

```tsx
import { Metadata } from "next";

type Props = {
  params: Promise<{ id: string}>
}

export const generateMetadata = async ({ params } : Props) : Promise<Metadata> => {
  const id = (await params).id;
  return {
    title: `Product ${id}`,
  };
}

const page = async ({ params } : Props)=> {
    const id = (await params).id;
  return (
    <div>Product Details {id} </div>
  )
}
export default page
```

### Configuring Metadata
#### Metadata Rules

- Both `layout.tsx` and `page.tsx` can export metadata.
  - Layout metadata applies to all its pages.
  - Page metadata is specific to that page.

- Metadata follows a top-down order, starting from the root level.

- When metadata exists in multiple places along a route, they merge together.
  - Page metadata overrides layout metadata for matching properties.

- Example

```text
app/
├── layout.tsx
├── blog/
│   ├── layout.tsx
│   └── page.tsx
```

- Metadata Flow

1. Root `layout.tsx` metadata is applied first.
2. `blog/layout.tsx` metadata is merged with the root metadata.
3. `blog/page.tsx` metadata is merged last and overrides matching properties.

### Benefits

- Improves SEO (Search Engine Optimization).
- Controls page titles and descriptions.
- Enhances link previews on social media platforms.
- Allows metadata to be generated dynamically based on route parameters or fetched data.

## title Metadada
- Define document title
- Can be either a string or an object
- `template` will give template tiele to all its children. replacing only `%s` with the title described in the route page.
```tsx
export const metadata: Metadata = {
  // title: "Create Next App",
  title: {
    default: "Next.js Routing and Metadata",
  template: " %s | Next.js Routing and Metadata",
  },
  description: "Generated by create next app",
};
```

- To break away from the pattern defined in the root layout, we can set the title to absolute, which will make it ignore the parent title and use the one defined in the specific route page.

```tsx
export const metadata: Metadata = {
    title: {
        absolute: "Docs",
    }
}
```

## Active Links
- use `usepathname()` hook 
```tsx
const pathname = usePathname()
return (
  const isActive = pathname === link.href || (pathname.startsWith(link.href) && link.href !== "/")
<Link
className={isActive ? "font-bold" : "text-blue"}
href={link.href}
> {link.name} </Link>
)
```
